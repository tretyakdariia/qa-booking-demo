# QA Booking Demo

Учебный QA-проект по ручному тестированию сервиса бронирования и REST API.

## О проекте

Цель проекта — проверить основные сценарии бронирования на основе требований, подготовить тестовую документацию и выполнить проверки REST API.

В рамках проекта я работала как с позитивными пользовательскими сценариями, так и с негативными и граничными значениями.

## Что было выполнено

- анализ требований;
- составление и выполнение тест-кейсов;
- позитивное и негативное тестирование;
- проверка граничных значений;
- тестирование REST API;
- выполнение POST-запросов в Postman;
- проверка валидации входных данных;
- проверка обязательных полей;
- фиксация ожидаемых и фактических результатов;
- анализ неоднозначностей в требованиях.

## Проверенные сценарии API

В Postman были подготовлены проверки для различных сценариев, включая:

- успешное создание бронирования;
- время вне доступных слотов;
- дату за пределами разрешённого периода;
- минимальную длину имени;
- количество гостей вне допустимого диапазона;
- различные форматы номера телефона;
- дату в прошлом;
- отсутствие обязательного поля.

## Анализ требований

В процессе тестирования были выявлены моменты, требующие дополнительного уточнения:

1. Для поля «Имя гостя» указана минимальная длина, но не определена максимальная.
2. Указано, что в имени допустимы буквы, но не уточняется, разрешены ли одновременно кириллица и латиница.
3. В задании требуется указывать фактический результат выполнения тест-кейса, однако в исходном шаблоне соответствующий столбец отсутствовал.
